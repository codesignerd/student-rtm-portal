## 1. Prerequisites: Manual Supabase Auth Account Creation

Supabase Authentication manages user credentials independently from public database tables. In accordance with the security architecture:
- Passwords are **never** stored or hashed in `public.users`.
- The user account must be created first in Supabase Auth so that a genuine UUID is generated by `auth.users`.

### Step 1: Create the Demo Student in Supabase Auth
1. Open your **Supabase Project Dashboard**.
2. In the left navigation, navigate to **Authentication** $\rightarrow$ **Users**.
3. Click **Add User** $\rightarrow$ **Create User**.
4. Enter the demonstration credentials:
   - **Email:** `demo.student@fedpoffa.edu.ng`
   - **Password:** `DemoStudent2025!` *(or any secure test password you prefer)*
   - **Auto Confirm User:** Toggle **ON** (so the account is immediately active without email verification).
5. Click **Create User**.

### Step 2: Copy the Generated Auth UUID
1. In the Supabase **Users** table, find the newly created account `demo.student@fedpoffa.edu.ng`.
2. Locate the **User UID** column (e.g., `a1b2c3d4-e5f6-7890-abcd-ef1234567890`).
3. Copy this UUID string to your clipboard.

## 4. Verifying the Inserted Records in Supabase

You can run the following verification query in the Supabase SQL Editor to confirm the complete relational linkage:

```sql
SELECT 
    u.email,
    u.role,
    s.matric_number,
    s.full_name,
    s.department,
    s.level_of_enrollment,
    ses.session_name,
    sem.semester_name,
    c.course_code,
    c.course_title,
    c.credit_unit,
    r.score,
    r.grade,
    r.grade_point,
    r.remark
FROM public.users u
JOIN public.students s ON s.user_id = u.user_id
JOIN public.results r ON r.student_id = s.student_id
JOIN public.courses c ON c.course_id = r.course_id
JOIN public.semesters sem ON sem.semester_id = r.semester_id
JOIN public.academic_sessions ses ON ses.session_id = sem.session_id
WHERE u.email = 'demo.student@fedpoffa.edu.ng'
ORDER BY c.course_code;
```

## 6. Critical Security Reminder: Protecting API Keys

> [!CAUTION]
> - **Never expose or use a Supabase `service_role` key in frontend code.**
> - The application frontend must only use the public anonymous key (`VITE_SUPABASE_ANON_KEY`) in `.env.local`.
> - All queries are protected by Row Level Security (RLS) policies based on `auth.uid()`.
> - Do not commit `.env.local` to Git.
